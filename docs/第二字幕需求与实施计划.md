# MPVPlayerKit 第二字幕需求与实施计划

日期：2026-10-15  
状态：六轮需求已确认；本文件为计划，尚未实施。  
范围：MPVPlayerKit、MPVQuickPlayerViewController、LuWu_iOS、Temby_iOS。

## 1. 目标与完成定义

新增与第一字幕能力对等的第二字幕。两路可以同时显示，所有可适用的设置、加载、取消、字体、自绘和公共接口均独立；修改、隐藏或重置一路，不影响另一路。第一字幕现有支持格式和使用方式保留。

完成不等于接入 `secondary-sid`：必须同时完成底层能力验证、双路状态与事务、QuickPlayer、两个宿主适配及实际播放验证。本轮仅完成调研、需求和计划文档，不修改产品源码、不构建、不运行播放器、不发布依赖。

## 2. 最终需求

以下为最终规则，覆盖访谈中被用户修订的旧建议。

### 2.1 来源、选择与显隐

1. 菜单区分“第一字幕”“第二字幕”，两路各有来源选择、关闭、外挂加载与设置入口。第二字幕关闭时仍可预设样式。
2. 两路不能占用同一轨道或同一外挂来源；重复选择提示已被另一路占用，保持原状态，不交换、不抢占。
3. 不保存任何一路上次选中的轨道、外挂 URL、文档或精确来源；不实现跨播放会话的字幕来源恢复。
4. 同一播放会话内，换画质、转屏、画中画或引擎重建需要保留两路当前来源、显隐和手动操作状态，并在新轨道编号下重新解析。
5. 退出播放或切换另一视频后，丢弃上述选择运行态。重新打开相同视频仍重新按自动选择配置匹配。
6. 加载、切换失败仅回退对应一路到之前成功的完整状态；此前未开启则继续关闭。另一字幕及视频播放不受影响。
7. 隐藏后保留当前会话内来源，恢复显示不必重选；退出播放后不记忆这种临时显隐。

### 2.2 外观、布局与格式

1. 两路设置各自独立：字体、字号、粗体、文字颜色、描边宽度/颜色、阴影强度/偏移/颜色/半径、背景、位置、边距、样式预设及原始样式策略。
2. 第一字幕默认底部居中；第二字幕默认顶部居中。两路都支持顶部/底部及距对应边缘的距离设置。
3. 第二路首次建立独立配置时，复制当时第一路的外观和字体，位置改为顶部；之后互不联动。延迟不参与复制。
4. 每个宿主独立长期保存两路外观、字体、位置及自动选择配置；LuWu 与 Temby 不跨 App 同步。
5. 保留第一路已保存配置，迁移为第一路配置；第二路独立初始化。恢复默认只改变对应一路。
6. 每个宿主的第二路控件范围与其第一路现有控件范围对等。原来仅有公共 API 的能力，为第二路提供对应 API，不顺带补齐所有缺失 UI。已确认的两路位置和自动语言设置需补充。
7. 保留 SRT/VTT 等文本、ASS/SSA、图片字幕及宿主文档自绘的现有能力范围。图片字幕本来不适用字体、字号等文字属性，两路限制一致并清晰提示。
8. 原始 ASS 模式优先保留文件字体、颜色、定位和特效，冲突的播放器样式/位置控件禁用并解释；延迟和显隐仍独立可用。切换到播放器样式时应用已存配置，不丢设置。
9. 不自动避让、不自行缩小或隐藏字幕。复杂 ASS、位图或用户将两路都设在同侧时，允许按原排版/用户设置重叠，通过手动设置解决。
10. 不能把去格式的文本自绘视作完整 ASS 或位图支持；不能以共享样式冒充两路独立设置。

### 2.3 自动选择

1. 两路分别保存自动选择开关与一个目标语言；第一路迁移宿主已有偏好，第二路自动选择首次默认关闭。
2. 首版目标语言：简体中文、繁体中文、英语。QuickPlayer 和 Temby 提供一致的选择范围；两路可以配置相同语言。
3. 开启自动选择后，每次打开视频/下一集重新匹配，不恢复上次轨道。关闭第二路自动选择时，第二字幕初始关闭，手动选择后才显示。
4. 先确定第一路，再为第二路排除已占用来源；第一路没有匹配项不妨碍第二路匹配。
5. 先比较语言匹配准确度；语言标记不足时结合标题、文件名区分。相同匹配得分下依次优先：非强制完整字幕、默认标记、文本、外挂、列表顺序。
6. 无匹配项保持关闭，不随意选其他语言；未手动操作时，候选稍后到达可继续自动匹配。
7. 用户手动选轨、加载外挂或关闭某一路后，本视频播放期间自动流程不覆盖该路；此抑制状态按路隔离，换视频重置。
8. 两路并发自动/手动选择仍执行来源占用检查，迟到结果不得改变更新的决定。

### 2.4 延迟：最终修订

1. 两路初值均为 0 秒。延迟只对当前播放有效，不写本地 UserDefaults、MMKV 或其他长期存储，也不写入外观配置。
2. 延迟在当前会话内跟随具体字幕来源：新来源读取服务端有效值，否则 0；切回本会话已调来源恢复内存值。
3. 临时隐藏、换画质、画中画、引擎重建保留本会话校时；退出或换视频清空。
4. 服务端明确支持且能准确归属当前用户、视频和字幕时，读取并保存其延迟。不能因协议存在 `SubtitleOffset` 字段就推断支持持久化。
5. 服务端不能区分两路时，不把两路不同延迟写到同一字段；不改原字幕文件，不写影响其他用户的共享值。
6. 无对应服务端或不支持时，仅当前播放有效。保存失败不回退已生效值、不阻塞播放，提示未保存到服务端。
7. QuickPlayer 两路延迟 UI 为 −60～+60 秒；底层 API 和 Temby 不因本次变更擅自缩窄其既有范围。单位换算集中在服务端适配层。
8. 停用 Temby 旧的本地延迟读写；旧值不得迁移为新的长期延迟配置，也不得随外观复制到第二路。

### 2.5 Temby 服务端烧录

1. 真正烧入视频像素的字幕不具备客户端独立显隐、校时和排版能力，不能作为双字幕独立控制的降级方案。
2. 双字幕使用独立可加载资源。第一路已烧录时，开启第二路先尝试无烧录视频及两路独立资源，保持播放进度和播放/暂停意图。
3. 资源或无烧录视频不可用时，提示无法开启，保持原播放状态；切换中途失败也应恢复原播放。
4. 既有单字幕烧录流程可保留，但不能将其标记为已经满足双路独立设置。
5. 自动选择图片字幕同样遵循以上规则，不能绕过能力校验隐式触发双路烧录。
6. 独立字幕端点能构造 URL 不代表全部格式可交付；PGS/SUP、VobSub 配对资源等需真实能力验证。

## 3. 持久化与生命周期矩阵

| 数据 | 本地长期保存 | 当前播放内存 | 服务端 |
|---|---|---|---|
| 两路外观、字体、位置/边距、样式策略 | 各宿主各路保存 | 保持当前值 | 无新增同步要求 |
| 自动选择开关、目标语言 | 各路保存 | 控制本片匹配 | 第二路不覆盖服务器现有单路偏好 |
| 所选轨道、外挂来源、文档 | 不保存 | 保留到退出/换片 | 不新增来源记忆 |
| 临时显隐、手动优先标记 | 不保存 | 换画质/重建保持 | 不保存 |
| 字幕延迟 | 不保存 | 按来源保留到退出/换片 | 仅明确支持且归属准确时读写 |
| 下载任务、requestID、epoch、临时文件 | 不保存 | 按会话/路别管理 | 不适用 |

没有本地逐媒体字幕选择/延迟数据库需求。宿主媒体身份仍用于异步过期判断、当前会话重建和服务端请求，不为本次功能新增文件指纹或改名追踪系统。

## 4. 已核实的技术约束

### 4.1 依赖

- `MPVPlayerKit/Package.swift` 精确依赖 MPVKit 1.0.0，revision `288527dffbc6d3e63cce147fc7b520c64a791603`。
- 官方构建脚本、release 说明确认基于 mpv v0.41.0。本机缓存库字符串为 `mpv v0.41.0-dirty`，完整引擎 commit 与构建修改全集未知，不能只按包版本假设可复现。
- 0.41.0 独立支持 `secondary-sid`、`secondary-sub-delay`、`secondary-sub-pos`、`secondary-sub-visibility`、`secondary-sub-ass-override`。
- 字体、字号、颜色、粗体、描边、阴影、对齐/边距及 `sub-scale` 等仍共享。之后增加的 `secondary-sub-scale` 也不等于完整样式独立。
- `secondary-sub-text` 不含位图，去格式文本不能重建复杂 ASS；该版本没有对等第二路 ASS extradata 接口。
- 同一 track ID 不可同时占用两路；外挂来源需要应用层额外去重。

### 4.2 当前代码

- 字幕存在三种路由：libmpv 原生；libmpv 解码文本后 UIKit 自绘；宿主 `MPVSubtitleDocument` 自绘。
- 当前多种路由共享一份逻辑选择、renderer/controller、样式、字体能力、延迟和加载选择代次。
- 当前加载回滚快照不含全部文档/renderer/样式状态，不能直接满足“失败完整恢复”。
- `sub-add` 默认会选择主字幕；第二路必须采用加载后明确选轨的流程。`sub-remove` 应显式给轨道 ID，不能误删第一路。
- QuickPlayer 现有控件包括预设、字号、粗体、阴影强度/半径、底部偏移、延迟；字体/颜色/描边等部分能力仅有 API。
- PiP 搬移整个 `MPVPlayerView`；应在同一视图内安装两路呈现，不另建播放器或视频解码链。
- LuWu 直接使用 QuickPlayer；Temby 使用自定义控制层和 `MPVPlayerView` 桥接，必须分别适配。

### 4.3 服务端延迟核查

当前没有充分证据确认 Emby/Jellyfin 提供可供 Temby 使用的长期字幕延迟保存和恢复契约；不能承诺已支持。

- Temby `CacheManager.subtitleDelay` 当前以 MMKV 键 `subtitle_delay_tenths` 长期保存 `round(秒 × 10)`。需停用 `VideoSubtitleSettingAlertView.swift` 的初始化读取、增减写回，以及 `MyVideoPlayerView+Subtitles.swift` 刷新时的旧值读取；仅改设置面板初始化不足以避免旧值重新生效。
- Temby `PlayState`/`PlayStateModel` 虽有 `SubtitleOffset`，未发现现成应用链路；当前进度请求没有提交该值，不能把字段存在当作已实现记忆。
- Emby 官方公开资料列出 `SubtitleOffset`/`SubtitleOffsetChange` 和实时播放状态字段，但尚未确认单位、正负方向、跨会话读写及用户/媒体/字幕流作用域。资料部分来自官方页面搜索摘要，正文抓取失败，需后续以完整协议进一步核实。
- 本次检索未确认 Jellyfin 的字幕延迟持久读写契约，也未确认任一服务器的两路独立延迟或客户端自备外挂保存契约；不是断言所有版本均不支持。
- 启用条件必须同时有明确的版本、单位/方向、身份作用域、持久写入和重开读取契约。未满足时两路均只保存会话内值，不盲目上报或伪造第二路字段，不因此新增服务器插件。

## 5. 推荐实施架构

### 5.1 方案取向与先决验证

以“一条视频/音频播放管线 + 两路字幕状态”为基础，保留已存在的三种渲染来源。纯文本及文档使用各自 UIKit 呈现；ASS/位图继续走适合其格式的原生路径。

优先验证最小定制 mpv 方案：将现有原生样式数据及其变更通知按字幕路别拆分，保留主路选项的兼容语义，补齐第二路所需属性与独立读取/应用。字体注册可以进程共享，字体选择必须按路独立。不得通过反复改共享属性在两路间“轮流套样式”。

不预先宣称定制方案已可行：版本/补丁基线、原生样式隔离、位图定位、字体和 ASS 路由都需先做最小能力验证。如果验证不能满足已确认格式及设置范围，记录具体阻塞后重新评估；不静默退化为只支持 SRT 或共享样式，不先完成整套 UI 再发现底层不可用。

### 5.2 双路模型与接口

建议引入明确路别（例如 `MPVSubtitleSlot.first/second`，命名在实施时遵循项目风格），分离：

- 偏好配置：外观、位置、样式策略、自动选择开关及目标语言；不含延迟/来源。
- 路别运行态：所选来源、可见性、路由、字体能力、手动优先、pending 请求和完整已提交状态。
- 播放会话态：媒体身份、会话代次、共享轨道目录/来源占用、内存校时缓存、资源清理。

现有 Swift 与 ObjC 无路别接口默认作用于第一路，新增显式路别入口。新增通知/结果包含路别与 requestID；保留旧调用的行为兼容，不能让两个 completion 都响应同一条不区分路别的事件。

不要以 `MPVMediaTrack.isSelected` 单个 Bool 推断路别；结合 `sid`、`secondary-sid`、`main-selection` 和应用已提交逻辑状态查询。`currentSubtitleText`、字体能力、renderer/document 操作均需路别入口。

### 5.3 加载、取消与提交

- MPV 调用仍在现有串行队列；UIKit/公开状态遵守 MainActor，跨域快照满足 Swift 6 并发约束。
- 隔离会话代次、每路选择代次和请求 ID，HTTP 下载完成、命令回复、超时及取消均校验归属。
- 选轨在提交前检查全局来源占用；加载轨不立即改变另一字幕。先取得确切新轨 ID，再选择目标路并回读确认。
- 共享资源与订阅取消分离：取消一路不能结束另一路仍使用的下载/字体/临时文件，销毁时统一释放。
- 完整回滚覆盖来源、原始样式策略、路由、文档、renderer、字体/能力、延迟、外观和显隐；自绘旧内容不要在新选择确认前不可逆清空。
- 已完成/过期/取消的请求不能重复回调，也不能因迟到回复恢复错误字幕或重新开启用户已关闭的字幕。

### 5.4 布局与自绘

- 两个独立 presentation controller/renderer 实例或同等的按路呈现状态，不能两路共用一个有状态 renderer 实例导致相互 clear。
- 保持旧的无路别自绘 API 作用于第一路；增加第二路自定义 renderer 安装、文档选择、清除和文本查询能力。
- 使用顶部/底部锚点和对应边缘距离；旧 `bottomOffset` 调用保留第一路底部语义，新接口表达位置与边缘距离。
- 核实原生与 UIKit 单位换算，避免原生重复加默认边距；保证第二路独立并维持第一路兼容。
- 原始 ASS 模式显示真实可用能力；位图文字控件禁用，不能显示可编辑却无效果。

### 5.5 自动选择与服务端职责

- Kit 提供可复用的语言归一化、候选排序和按路选择协调；Temby 提供服务器流、语言及可交付资源元数据，避免两套规则漂移。
- UI/存储由 QuickPlayer 和 Temby 各自适配，共用语义；MPVPlayer 核心不直接依赖 Temby CacheManager。
- 服务端延迟放宿主适配层，Kit 提供按路/来源应用与读取当前延迟的接口。依据真实协议能力启用，不能为“可能支持”引入无证据写请求。
- 同一来源的会话内校时优先于稍后到达的服务器初始值；过期读取/保存回复不能污染新来源或新会话。
- 服务端现有单路进度上报与双路选择是不同职责，不将第二路覆盖写入第一路的 SubtitleStreamIndex/用户语言设置。

## 6. 实施阶段与完成门槛

| 阶段 | 工作与主要文件范围 | 必须满足的完成门槛 |
|---|---|---|
| P0 基线与能力验证 | 精确 MPVKit/mpv 构建基线、最小双路样式补丁验证；Temby 独立图片交付及服务端延迟协议 | 证明两路可适用设置不串路；明确构建来源/架构；列出服务器确切支持与不支持，不能猜测 |
| P1 依赖与公共模型 | 确认可复现补丁并本地构建产物；Package.swift/resolved；MPVPlayerModels、Player/View、Bridge、ConfigurationSnapshot | 两路接口明确；旧接口默认第一路；依赖可构建；未发布外部产物 |
| P2 双路运行管线 | Playback、Events、ClientSubtitles、SubtitleRenderer、SubtitleFont、Setup/Teardown、ProfileFallback、文本缓存 | 双路原生/自绘、字体/样式、显隐/延迟独立；并发加载/取消/回滚与重建保持正确 |
| P3 QuickPlayer | Controller/Settings/Controls/Delegates、SubtitleSettingsView、Resources、本地偏好迁移 | 两路菜单及现有设置对等，顶/底布局、自动语言、配置保存；不保存来源/延迟 |
| P4 Temby | MPVPlayerEngine/VideoPlaybackEngine、MyVideoPlayerView+Subtitles、VideoPlayVC字幕/控制/异步、CacheManager和服务器适配 | 单路状态拆分，双路UI/语言/资源可用；旧本地延迟停用；烧录转换失败可恢复原播放 |
| P5 LuWu 集成 | VideoPlayerPresenter、普通/保险箱/包内播放列表适配（仅必要处） | QuickPlayer双字幕可用，临时HTTP来源不污染长期配置；换片清理和PiP一致 |
| P6 验证与文档 | 针对性自动化、Demo/模拟器及真机验证、README/接入示例 | 下方矩阵通过；能力限制/服务器条件有据可查；没有无关改动 |

顺序：P0 → P1 → P2 → P3/P4 → P5 → P6。底层门槛不过，不进入大规模产品接线。P3/P4 可以在稳定接口后分别开展，但保持单一共享模型与计划所有者。

代码按现有目录和命名风格拆分，单文件不超过 600 行；不借机重构无关播放、加密或媒体业务。外部依赖发布、上传构建产物不属于本计划的默认执行动作。

## 7. 设置对等清单

| 能力 | 第一/第二路要求 | UI或格式边界 |
|---|---|---|
| 来源/外挂/取消/显隐 | 完全独立 | 不重复占用，状态标明路别 |
| 字体注册/选择/重置/能力 | API对等，选择独立 | 图片不支持；字体文件可用性需检查 |
| 字号/粗体/文字色 | 独立 | 各宿主沿用现有控件范围；ASS原样式限制一致 |
| 描边宽度/颜色 | 独立 | 现有API能力不遗漏 |
| 阴影强度/偏移/颜色/半径 | 独立 | 自绘/原生按真实可用能力提示，不能一边改另一边 |
| 背景色/预设 | 独立 | 保留原生和自绘现有适用限制，不冒充全格式可用 |
| 顶/底位置、边缘距离 | 两路提供 | 第一底部、第二顶部；不自动碰撞避让 |
| ASS原样式/播放器样式 | 两路提供 | 原始脚本优先，配置保留 |
| 延迟 | 每来源会话内独立 | 不本地长期保存，服务端条件保存 |
| 自动语言 | 两路提供 | 简中/繁中/英语，第二路默认关闭 |
| 自定义renderer/文档/文本查询 | API对等 | 去格式文本不替代完整ASS/图片 |
| PiP/转屏/换画质/重建 | 两路连续 | 同会话恢复，换媒体清理 |

## 8. 验收矩阵

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 文本+文本、文本+ASS、ASS+ASS、文本+PGS、位图+位图，含内嵌/外挂组合 | 有合法独立资源时两路可显示；所有适用设置独立；格式限制一致 |
| A02 | 分别调整字体/字号/颜色/描边/阴影/预设/位置/延迟，隐藏及重置一路 | 另一字幕状态、外观和视频不变；旧API仅影响第一路 |
| A03 | 第二路首次配置、已有第一路偏好升级、App重启 | 首次复制外观但顶部；之后独立持久；不复制/恢复轨道或本地延迟 |
| A04 | 自动语言三种选择、同语言多轨、forced/default/图片/外挂、缺失语言、候选迟到 | 符合语言得分与稳定排序；先第一路后第二路；无匹配不乱选 |
| A05 | 同轨/同外挂重复选择，自动与手动并发冲突 | 拒绝占用，不抢另一字幕，不产生第三份或重复来源 |
| A06 | 用户选轨/加载外挂/关闭后，晚到候选和下载回复 | 不重新自动覆盖该路；另一路仍按自身规则执行 |
| A07 | 两路同时下载、取消其中一路、超时/HTTP失败/命令失败/取消迟到回复 | 每请求至多一次完成，失败完整回退对应路，资源不串删 |
| A08 | 原始ASS/播放器样式切换、位图字体控件、同侧位置重叠 | 原样式优先且提示明确，切换不丢配置；不隐式避让 |
| A09 | 来源A校时→B→A、暂时关闭→恢复、换片/退出/重开 | A会话校时恢复；B独立；结束后本地无延迟/来源记忆 |
| A10 | 服务器支持/不支持/只单字段/网络失败/旧回复 | 准确归属才读写；不覆盖两路；失败保持当前效果并提示；无共享文件修改 |
| A11 | 双路下转屏、fit/fill、PiP进出、换画质/引擎重建 | 两路显示和校时连续，重建重新解析ID，无重复渲染 |
| A12 | Temby烧录第一路→开启第二路，资源缺失/无烧录源失败/重载失败 | 成功得到独立双路；失败原播放可恢复，无假独立控制 |
| A13 | LuWu普通文件、保险箱视频、包内视频、播放列表切换 | 双路可用；换片清理；临时来源不持久；加密流生命周期正常 |
| A14 | 调用层兼容、诊断、资源释放 | Swift/ObjC旧接口兼容；诊断含路别不含字幕正文/敏感URL；停止后任务/文件清理 |

自动化重点放在来源占用、自动选择、生命周期、请求归属、完整回滚、配置迁移和服务端适配。视觉与系统行为通过实际播放器验证；模拟器适合交互/时序，字体附件、复杂ASS、HDR/PiP及功耗等仅在适用真机上作结论。测试素材使用可控合法文件，不把测试存在当作通过证据。
