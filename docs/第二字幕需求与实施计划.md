# MPVPlayerKit 第二字幕需求与实施计划

更新：2026-10-16

状态：Q24～Q26 已确认；用户于2026-10-16授权按本计划开发，R0～R5实施中。

适用：当前 MPVKit 1.0.0 / mpv 0.41.0 原版依赖。

## 1. 当前目标与范围变更

使用现有 MPVKit/libmpv API 实现“公共样式 + 两路独立播放控制”。覆盖 MPVPlayerKit 公共接口、MPVQuickPlayerViewController、LuWu 和 Temby 自定义播放器入口。

本版本取代此前“所有可适用样式完全独立、保留完整格式并通过定制依赖补齐”的开发目标。以下内容退出实施范围：

- 定制或升级 mpv/MPVKit、重编译 FFmpeg、引入 P0 实验补丁或实验库。
- 第二路 UIKit 自绘、第二路文档 renderer，以及借此实现独立字体、颜色、背景或阴影半径。
- 外挂 SUP/VobSub 解复用能力补齐、字幕格式转换、提取/OCR、新增字幕解码链。
- 两份独立原生外观配置、独立精确像素边距、自动碰撞避让。

[历史 P0 报告](第二字幕P0能力验证报告.md)保留实验事实。其整体 No-Go 针对旧目标，不再要求先完成定制库或全格式扩展才能执行本计划；实验补丁通过也不代表原版具备相同能力。新范围仍需针对原版依赖完成下述接入与验收。

## 2. 功能与 API 映射

| 功能 | 第一字幕 | 第二字幕 | 当前约束 |
|---|---|---|---|
| 选轨/取消选择 | `sid` | `secondary-sid` | 同轨不能重复占用 |
| 显示/隐藏 | `sub-visibility`或第一路现有呈现逻辑 | `secondary-sub-visibility` | 隐藏与取消选择区分；不互相清空 |
| 延迟 | `sub-delay`或第一路现有校时 | `secondary-sub-delay` | 单位秒，两路独立 |
| 垂直位置 | `sub-pos`及第一路现有布局适配 | `secondary-sub-pos` | 原生0～150；不是像素边距 |
| ASS覆盖策略 | `sub-ass-override` | `secondary-sub-ass-override` | 策略各自独立，覆盖所用样式仍共享 |
| 字体、字号、粗体、颜色、描边、阴影 | 一份公共样式 | 同一份公共样式 | 按格式、路由和覆盖策略应用 |
| 外挂加载 | `sub-add URL auto`后显式选择目标 | 同左，设置`secondary-sid` | 命令回复后识别准确轨ID；不默认选第一路 |
| 外挂移除/重载 | `sub-remove ID` / `sub-reload ID` | 同左 | 显式ID，重载后重新识别轨道 |
| 文本/时间读取 | `sub-text`等现有入口 | `secondary-sub-text`、`secondary-sub-start/end` | 位图无纯文本；不据此重绘完整ASS |
| 语言自动选择、去重、回滚、配置保存 | 应用层实现 | 应用层实现 | 复用现有API，不扩展底层能力 |

## 3. 界面与配置规则

### 3.1 公共样式

1. 菜单提供“字幕公共样式”，字体、字号、粗体、文字色、描边宽度/颜色、阴影等原生共享设置只保存一份。
2. 明确说明公共样式作用于两路可适用字幕。修改或恢复公共样式可同时影响两路，这是预期行为，不再承诺外观互不影响。
3. 各宿主沿用第一字幕已有控件范围，不补齐原来仅API提供的所有控件。公共API中的共享样式也应如实命名和说明。
4. 第一字幕现有UIKit文本/文档自绘保留；将公共样式可支持字段同步给现有renderer，不承诺它与原生渲染完全一致。
5. 背景、阴影半径等仅现有自绘支持的能力保留在第一路原有适用范围，不能呈现为第二路可独立或必然生效的控件。
6. 迁移以现有第一路样式作为公共样式，不建立第二份外观副本；字体选择/重置为公共操作。LuWu和Temby各自保存，不跨App同步。

### 3.2 两路控制

1. “第一字幕”“第二字幕”各有来源选择、关闭/显隐、外挂加载、延迟、垂直位置、ASS模式、自动选择开关和目标语言；不再要求两路设置页面完全同构。
2. 第二路首次默认关闭，自动选择首次默认关闭；第一字幕保留现有初始行为与偏好。
3. 默认第一路底部、第二路顶部。两路可通过各自垂直位置调整；原生范围0～150，默认第一路100、第二路0。UI可提供顶部/底部快捷值及位置调整。
4. 第一路已有底部距离接口及自绘布局保持兼容，但不把共享`sub-margin-y`包装为第二路独立边距；涉及原生共享参数时标明共同作用，避免多处配置相互覆盖。
5. 分别长期保存位置、ASS策略和自动选择偏好；不长期保存实际选中的轨道、外挂来源、文档或临时显隐。
6. 两路不能选择同一轨道/同一外挂来源；提示占用并维持原状态，不交换、不抢占。加载失败只恢复对应路之前的成功选择/路由/显隐/校时，不回写旧公共样式覆盖用户的新设置。
7. 恢复某路默认控制项只影响该路；恢复“公共样式”允许影响两路，不将两种操作混在同一按钮含义中。

### 3.3 原始样式与格式限制

- 原始ASS模式优先脚本字体、定位和特效，保留该路已设的播放器策略值但不强制覆盖原排版；切回播放器样式再应用公共样式。延迟和显隐保持独立。
- 一路原始ASS不能使另一字幕的公共设置入口整体禁用；界面说明该路不接受哪些覆盖。公共设置是否可用依据实际受影响的字幕，而不是仅看第一路。
- 图片字幕不提供字体/颜色等文字样式效果。垂直移动遵从现有原生限制，不保证任意图片块都能定位或避开另一字幕。
- 仅使用当前原版依赖可加载的资源；内嵌图片轨可在实际可解码时使用。P0已发现当前iOS缓存FFmpeg缺少外挂SUP/VobSub解复用器，不能使用重建库实验的成功结果宣称原版支持。
- 加载不支持格式、资源空内容/超时或解码失败，提示对应路失败，保留原选择；不转换格式、不新增渲染器、不烧录降级。
- 不自动避让、不自行缩小、挪动或隐藏字幕。原始ASS或位图重叠允许用户手动调整可用设置。

## 4. 自动选择、会话与延迟

### 4.1 自动选择

- 两路独立保存自动开关和一个目标语言：简体中文、繁体中文、英语。第一路迁移既有偏好，第二路自动默认关。
- 每次打开视频/下一集重新匹配，先第一路后第二路，第二路排除占用来源；第一路无匹配不阻止第二路匹配。
- 优先语言匹配得分；标记不足时用标题/文件名辅助；同分依次比较非forced完整字幕、default、文本、外挂、稳定列表顺序。
- 候选必须在当前依赖/资源能力范围内；明确不支持的来源不进入自动候选。不因某路图片候选触发双路烧录。
- 无匹配保持关闭；轨道稍后到达可继续匹配。用户手动选轨、加载外挂或关闭某路后，本视频内自动结果不得覆盖该路；换视频解除抑制。

### 4.2 生命周期

- 同一播放会话内换画质、转屏、PiP或引擎重建，保留两路当前来源、校时、显隐及手动优先状态，重新解析轨ID；旧下载/命令回复不得污染新会话。
- 退出或换另一视频丢弃选择及校时；重新打开同视频也不恢复上次来源，按自动偏好重新匹配。
- 第一路文档自绘仅处理第一路，不关闭/清除第二路原生字幕。原生显隐不等于逻辑显隐，查询和诊断须区分。
- PiP沿用现有整视图移动机制，验证第二路随现有视频渲染保留，不新增PiP或视频管线。

### 4.3 延迟

- 两路默认0秒，按当前播放中的具体字幕来源在内存保留；新来源读服务端明确支持的值，否则0；切回本会话已调来源恢复内存值。
- 不写本地长期配置，不随公共样式保存，不继承Temby旧MMKV延迟；停止设置面板、刷新路径对旧键`subtitle_delay_tenths`的长期读写。
- QuickPlayer两路延迟UI沿用−60～+60秒；底层/Temby保持既有范围，不因本次缩窄。
- 仅服务端有明确的单位、方向、用户/媒体/字幕作用域及跨会话读写契约时才保存；两路不能写同一无法区分来源的字段，不改字幕文件/共享数据。
- 当前未确认Emby/Jellyfin满足上述保存条件，本版按会话内生效处理，不为此新增服务器协议、插件或试探性写入。将来若有明确现成能力再按同一规则接入。
- 保存失败保持当前效果并提示未保存，不阻塞播放；过期服务端回复不能覆盖当前新来源校时。

### 4.4 保存矩阵

| 数据 | 本地长期 | 当前会话 | 服务端 |
|---|---|---|---|
| 公共样式/公共字体 | 每宿主一份 | 当前值 | 不新增同步 |
| 第一路已有自绘专用设置 | 保持现有适用配置 | 仅第一路 | 不同步 |
| 每路位置、ASS策略、自动开关/语言 | 按路保存 | 独立应用 | 不覆盖现有单路服务器偏好 |
| 所选轨道/外挂/文档、临时显隐、手动优先 | 不保存 | 重建保持，退出/换片清空 | 不新增选择记忆 |
| 延迟 | 不保存 | 按来源保留 | 仅明确满足契约时读写；当前未确认 |
| 请求、轨ID映射、临时文件 | 不保存 | 按会话/路管理及释放 | 不适用 |

## 5. Temby与LuWu集成边界

Temby使用MPVPlayerView桥接和自定义界面，需适配双路控制及公共样式。既有单路服务端烧录可以保留；双路仅接受可独立加载资源。第一路已烧录时，开启第二路可沿既有换源流程尝试无烧录视频和独立资源，保留进度及播放意图；资源不可用或切换失败则恢复原播放并提示。不增加字幕提取、格式转换或转码策略来绕过限制；也不把一条已烧录像素字幕显示为可独立控制。

LuWu通过QuickPlayer获得功能；普通文件、保险箱及包内媒体只做必要生命周期适配和验证，不为记忆来源新增永久媒体ID或文件指纹系统。临时HTTP地址不得进入长期配置。

Temby的其他播放内核不因本次任务增加第二字幕功能；公共设置与协议需向后兼容，只有MPV路径声明对应能力，不能让其他内核出现无效果入口。

## 6. 推荐实现结构与变更范围（尚未执行）

1. **共享样式与两路运行态分开。** 保留MPVSubtitleStyle公共语义；增加明确路别和按路控制/状态。第一路现有自绘专用字段保留适用限制。没有第二份原生字体/颜色配置。
2. **接口兼容。** 原有无路别选轨/延迟/显隐/自绘接口默认第一路；原有样式与字体API映射公共样式，并注明对第二路原生字幕的共享影响。新增显式第二路控制及文本读取入口，不新增第二路renderer/document入口。
3. **事务隔离。** 复用MPV串行队列；按会话、路别和requestID隔离下载、选轨、取消、超时、回调和回滚。共享轨道目录统一管理占用；重载后ID重新识别。先加载后显式选目标，避免`sub-add`默认抢第一路；删除显式传ID。
4. **兼容原有渲染。** 第一路native、decoded-text→UIKit、文档自绘保持原能力；第二路始终通过原生secondary属性显示。清理或隐藏第一路renderer不得写第二路状态。
5. **运行时能力。** 使用原版可查询属性与实际加载结果，提供格式/控件能力提示。初次应用和回读须检查错误，不能命令返回成功就声称有可见内容。
6. **生命周期。** 已提交快照保存对应路来源、原始模式、路由、显隐和会话校时；公共配置独立维护，取消/回滚不恢复过时公共配置。图像、字体注册及下载资源的释放不能删除另一条仍在使用的资源。
7. **并发与诊断。** Swift6、MainActor及现有串行队列边界保持；结果携带路别/requestID，兼容旧通知。诊断记录路别和能力，不记录正文、凭据或敏感URL。

主要文件范围：MPVPlayerModels、MPVPlayer、MPVPlayerView及Playback/Events/ClientSubtitles/Diagnostics/Font/Setup/Teardown等扩展；QuickPlayer的Settings/Controls/Delegates/SubtitleSettingsView及本地化；Temby的MPVPlayerEngine、VideoPlaybackEngine、MyVideoPlayerView字幕状态、VideoPlayVC字幕菜单、CacheManager和设置面板；LuWu仅必要接入点。实施前读取最新源码，按现有架构拆分，单文件不超过600行，不清理无关代码。

## 7. 修订后的开发阶段

使用R编号区分历史P0～P6。2026-10-16用户已授权实施，以下阶段按依赖推进；实际完成与验收结果记录于开发验证报告。

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| R0 原版基线及能力清单 | 固定现有MPVKit版本/原版产物，核对已验证API与格式，确认无实验库链接 | Package/依赖不变；共享/独立/不支持矩阵准确；不再构建定制依赖 |
| R1 公共模型与桥接 | 一份公共样式、两路控制/状态/能力、兼容Swift及ObjC入口 | 旧控制默认第一路，样式共享影响明确；第二路无自绘扩展 |
| R2 运行管线 | 第二路选轨/加载/取消/显隐/延迟/位置/ASS模式/文本；第一路原生及自绘兼容；会话恢复 | 来源去重与异步归属正确，失败对应路回退，公共样式不被旧事务覆盖 |
| R3 QuickPlayer | 公共样式区、两路控制菜单、自动语言及配置迁移 | 两路可操作；共享样式提示准确；不保存来源和本地延迟 |
| R4 Temby适配 | 桥接/自定义菜单、共享样式、自动选择、能力提示、旧延迟停用及烧录边界 | MPV双路可用；其他内核兼容；不支持资源明确失败且保留播放 |
| R5 LuWu与回归 | 普通/保险箱/包内/列表、PiP和重建验证、测试及README | 下列新验收矩阵满足；限制有明确用户反馈 |

顺序：R0→R1→R2→R3/R4→R5。R0是原版依赖接入核对，不是重开旧的定制P0。开发已获授权，依赖与能力边界仍以本计划为准。

## 8. 新验收矩阵

| 编号 | 场景 | 通过标准 |
|---|---|---|
| V01 | 原版SRT/VTT/ASS及实际可用内嵌图片双轨 | 两路可同时显示；资源/原生格式限制清楚；不引入实验补丁 |
| V02 | 选轨、隐藏、延迟、垂直位置、ASS模式 | 两路独立；同来源拒绝；原始ASS/位图遵从实际布局限制 |
| V03 | 字体、字号、粗体、颜色、描边、阴影及重置 | 只有一份公共样式；按格式/覆盖模式影响两路；不验收独立外观 |
| V04 | 第一路UIKit文本/文档+第二路原生，背景/阴影半径 | 第一路能力兼容；清理/隐藏不影响第二路；专用字段不假装对第二路有效 |
| V05 | 三语言自动选择、多候选、同语言占用、晚到结果 | 排序稳定、先第一路后第二路、手动操作优先，无匹配关闭 |
| V06 | 外挂并发加载/超时/取消/迟到回调/失败 | 每请求至多完成一次，仅对应路回退，不抢另一轨或覆盖公共配置 |
| V07 | 外挂SUP/VobSub等原版不支持来源、空内容/网络失败 | 明确失败且保留旧状态，不转换、不重编译、不烧录降级 |
| V08 | App重启、换片、升级旧配置、恢复默认 | 一份公共样式和按路偏好保存；不记来源、显隐或本地延迟；第一路旧配置保留 |
| V09 | 来源A校时→B→A，隐藏、换画质、退出/换片 | 会话内按来源恢复，退出清空；不读取旧MMKV延迟 |
| V10 | 服务端延迟未确认/只支持单字段/保存失败 | 未满足契约不写；不混写两路，失败不回退当前校时 |
| V11 | PiP/转屏/fit-fill/句柄重建、停止释放 | 两路运行态连续，无双重显示；换片旧结果失效，资源正确清理 |
| V12 | Temby烧录→尝试双路、LuWu本地/保险箱/列表 | 可用独立资源成功；不可用保持原播放；临时地址不持久化 |
| V13 | 接口兼容/诊断/依赖 | 第一字幕现有调用保持兼容；第二路原生能力明确；依赖版本和产物未改 |

实现阶段运行针对性的状态/排序/事务/迁移测试，并用原版依赖实际验证UI和字幕显示。现有补丁实验不能替代新功能运行验证；未使用真机不作真机结论。精确边距、全格式、第二路自绘及完整样式独立不再是验收要求。
