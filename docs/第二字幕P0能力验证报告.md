日期：2026-10-15。范围仅 P0；未接入双字幕产品 UI、业务或 P1–P6。

## 结论

**整体仍 No-Go：当前不能进入 P1–P6。** 原版 MPVKit 1.0.0 已实测共享样式串路；最小补丁已在 macOS 与 iOS simulator arm64 实际编译、执行软件渲染。macOS 双 SRT / 双 ASS force、模拟器双 SRT 的双向修改与恢复序列均未发现跨路像素变化；两平台实际选中附件独有字体。macOS 外挂 SUP、受控 VobSub 配对及两平台内嵌 PGS 已显示并完成位置/延迟/显隐双向矩阵。缓存 iOS FFmpeg 缺少 sup/vobsub 解复用器的阻塞已在隔离重建中突破，两种外挂在模拟器实际显示并通过13帧双向控制；原发布依赖仍需整合。 完整平台补丁构建、全设置覆盖、真实服务器资源交付与 Metal/PiP 等仍未满足，不能据局部通过宣布 P0 全部通过。

这不是判定定制方案不可实现，而是 P0 门槛尚未通过。报告交付完成不等于能力验证全部通过。

## 3. 双路实际渲染实验

`probe.c` 编译与运行均退出 0。原生主路样式属性存在；`secondary-sub-font`、`secondary-sub-font-size`、`secondary-sub-color`、`secondary-sub-border-size`、`secondary-sub-shadow-offset` 读取返回 `-8`（属性不存在）。第二路位置、延迟和显隐均可写回读，第一路位置/延迟不随之改变。

`render.c` 使用 `MPV_RENDER_API_TYPE_SW` 渲染为 RGB，输出 PPM。两路分别选择 sid=1、secondary-sid=2，字幕事件从第 1 秒到第 8 秒，播放定位第 2 秒、暂停。两路 ASS override 均为 force，以测播放器样式；第一路在底部、第二路在顶部。每次设置后处理事件，再渲染并比较上下半屏逐像素变化。

### 8.4 iOS 模拟器

使用精确缓存 iOS 模拟器 arm64 静态库编译 probe.c，codesign 后由 `simctl spawn booted` 实际执行，编译和运行均退出 0；初始化成功、版本 mpv v0.41.0-dirty / FFmpeg n8.1.2，原版缺少独立第二路字体等属性与 macOS 一致。[编译及运行证据](../../.planning/2026-10-15-mpv-secondary-subtitle-design/p0-results/simulator/)

这是原版 C API 可执行路径验证；patched 库仍只有 macOS 软件输出构建。尚未交叉编译 patched iOS、模拟器实际渲染、Metal/PiP 或真机，不把原版探针代替这些条件。

### 8.5 服务器真实读取

必要测试认证 HTTP 200；读取媒体目录各页 HTTP 200，遍历至末页（StartIndex 0、200、400、600、800、1000、1200）。在返回媒体流中找到 124 个图片字幕候选，均为 PGS，未找到 VobSub 样本。

针对真实媒体的 PGS index 4、5 分别读取 Stream.sup 与 Stream.pgs：两次 sup 超过 40 秒无响应而超时；两次 pgs HTTP 200、Content-Type application/octet-stream，但正文均 0 字节。重试结果相同。脚本以 http=0 表示请求超时，**不是服务器返回 HTTP 0**。因此当前这两个样本不能交付可用独立图片字幕；不能推广为所有 PGS 媒体都不支持。[脱敏结果](../../.planning/2026-10-15-mpv-secondary-subtitle-design/p0-server-retry/summary.json)、[扩大样本查询后的结果](../../.planning/2026-10-15-mpv-secondary-subtitle-design/p0-server-vobsub-search/summary.json)

没有使用媒体播放进度/配置写入来测试延迟保存；现有公开契约仍不足以启用双路持久延迟。未请求会触发播放协商写流程的无烧录视频，故此项仍未知。

### 8.6 更新后的决策

**局部 Go：** 最小样式对象拆分在 macOS 软件输出的文本与 ASS force 路径已经实际证明可行，值得继续完成 P0；原生独立位置/延迟/显隐不需新增视频管线。

**整体 No-Go：** patched iOS 与完整构建基线、附件字体实际选择、外挂 SUP/位图全部适用设置、VobSub 配对和服务器有效资源交付仍未满足。继续仅处理这些 P0 门槛，不开发完整 UI 或业务。

### 9.3 外挂SUP黑屏定位与位图矩阵

为实验sd_lavc临时加入包/解码日志，确认原始SUP能解码出1秒开始的可见矩形和8秒清屏事件。旧程序在加载两条外部流后立刻跳转0，日志出现重读的END分段与0矩形清屏，之后画面全黑；同一库、同一SUP改为无跳转从头播放，基线实际17280非黑字节。因而此前黑屏不能归因于SUP不可解码；已定位为该极小分段样本的加载后跳转/分段重读路径。任意跳转和通用SUP兼容性仍不能据此宣布修复。临时诊断源修改已撤回，最终补丁仍只含四个样式文件。
